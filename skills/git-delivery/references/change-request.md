# Prepare or update a PR/MR

1. Verify the repository, host, remote, source branch, target and exact change range. Use the project's CLI, access path and request type. If the repo is local-only or the remote cannot be verified, report the limit; do not add a remote, change credentials or substitute another host.
2. Check the owned diff and required checks. Reuse evidence and independent review of unchanged content; review fixes only where they change the accepted snapshot. Do not run another cleanup or add a draft stage merely because the work moved from commit to PR/MR. Follow explicit project gates.
3. Push only the assigned branch, without force or unauthorized direct pushes. Look up the existing open request for the same source and target before creating one; update it if that is the assigned request. Apply project title, template and merge settings. Describe the user-visible change, exact checks and remaining limits; include affected counterpart repositories, mixed-version compatibility and migration ordering only where applicable. Do not leak credentials or private tracker references.
4. Verify the returned request URL, target, head and observed check state. Return the link, evidence, limitations and next owner action. Preparing a request does not authorize merge, auto-merge, release or deploy. Continue into delivery only under the project's rules and the assigned scope.
