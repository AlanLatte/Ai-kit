# Security review

Ai-Kit owns the generic engine. Project wrappers own target inventory, access and delivery restrictions; they cannot broaden execution authority. Resolve this effective skill and its real directory, not a guessed marketplace cache path. Project wrappers require Ai-Kit >=0.5.0.

- **Question or focused/scoped review:** read [shared safety and evidence](references/core.md), then only relevant [attack classes](references/ATTACK-CLASSES.md) and named domain companions. Do the requested scope completely; do not load the full audit workflow or write unrequested artifacts.
- **Explicit codebase audit, pen test, full/comprehensive/end-to-end security review:** follow all six phases in [workflow](references/workflow.md), with proportionate reconnaissance/hunting, deterministic coverage and independent confirmation.
- **Report artifact alone:** preserve the existing review scope and evidence bar. Writing a report does not request a broader full audit. Ask only if the actual target/scope is missing.

Source inspection is read-only. Target-controlled execution requires the workflow's complete OS-enforced sandbox, empty allowlisted environment, isolated network, scratch-only writes and resource limits; unavailable controls mean source-only work plus exact validation limits, not weaker execution. No live probes, shared services, real secrets, paid calls or target-source edits. Independently verify every confirmed finding; never turn a checklist gap or self-impact into a vulnerability.

Generic procedures and companions are in `references/`; schema and validators are in `vendor/`. Keep `vendor/LICENSE` and `vendor/UPSTREAM` with redistributed content. When drafting or substantially revising the narrative report, use `skill://no-ai-slop` once; structured findings, receipts and short statuses do not independently require it. Preserve source evidence, IDs, severity and required schemas.
